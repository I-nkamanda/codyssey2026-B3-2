# 요구사항 구현 점검

## 필수 기능

- 저장소 초기화·main·HEAD·작성자: `Repository.initialize`. 중복 초기화는 거절합니다.
- 브랜치 생성·전환·현재 HEAD를 부모로 하는 커밋: `branch`, `switch`, `commit`.
- hash/message/author/timestamp/parents: 불변 `Commit` 데이터 클래스.
- 세션 내 ID 유일성: 감소하거나 초기화되지 않는 Python 정수 카운터를 16진수로 표현합니다.
- DAG 유지: 생성 시 기존 노드만 부모로 사용하며 노드의 부모는 변경하지 않습니다.
- 해시맵 조회: `commits`, `branches` 딕셔너리.
- 단어 및 작성자 역색인: `keyword_index`, `author_index`. 검색은 전체 커밋 순회를 하지 않습니다.
- 공백 분리와 소문자 토큰: `message.lower().split()`. 여러 검색 단어는 AND 방식으로 해석합니다.
- 직접 구현한 정렬: `merge_sort`. 날짜·작성자 기준 오름차순, 안정 정렬.
- 부모 우선 LOG: `topological_order`의 Kahn 알고리즘. 모든 브랜치의 커밋을 대상으로 합니다.
- 최단 PATH 및 사전순 동률 처리: 이웃을 사전순으로 정렬한 무방향 BFS.
- 모든 조상: 방문 집합을 사용하는 반복형 DFS. 자기 자신 제외.
- REPL 및 따옴표: `repl`, `execute`, `shlex.split`. 명령 이름만 대소문자를 무시합니다.
- 오류 및 종료: 인자·존재 여부 오류를 출력하고 계속 실행. exit/quit/EOF/Ctrl+C 종료.
- 실행·문서: `main.py`, `README.md` 제공. Python 표준 라이브러리만 사용합니다.

## 선택 과제와 범위

MERGE로 부모가 둘인 커밋을 생성합니다. 빈 HEAD나 같은 HEAD 병합은 거절합니다. Diff 및 정렬 알고리즘 두 종류의 성능 비교는 미구현입니다. 실제 파일 추적, 저장소 영속화, 네트워크 통신은 과제 범위에서 제외합니다.

## 자동 검사 내용

`python -m unittest discover -s tests -v`로 검사합니다.

- 분기 이후 각 부모가 올바른지 확인합니다.
- 병합 커밋의 두 부모와 모든 조상을 확인합니다.
- 전체 LOG에서 모든 부모의 위치가 자식보다 앞인지 확인합니다.
- 양방향 이동, 같은 출발·도착점, 연결 없음, 같은 길이의 경로 선택을 확인합니다.
- 정확한 토큰·대소문자 정규화·복수 단어·작성자 인덱스를 확인합니다.
- 전체 커밋 순회를 금지한 저장소에서도 검색이 동작하는지 확인합니다.
- 정렬의 순서·안정성·입력 보존과 작성자·날짜 정렬을 확인합니다.
- 1,200개 커밋의 ID 유일성과 깊은 이력 탐색을 확인합니다.
- 따옴표·명령 대소문자·오류 메시지·실패 시 기록 보존을 확인합니다.
- 정렬 금지 API 호출 여부를 소스 구문 트리로 확인합니다.
- 비정상 순환 그래프를 위상 정렬이 거절하는지 확인합니다.

GitHub 자동 검사는 Linux의 Python 3.10, 3.12, 3.14에서 실행되도록 설정했습니다. 실제 원격 검사 결과는 업로드 후 Actions에서 확인해야 합니다.
